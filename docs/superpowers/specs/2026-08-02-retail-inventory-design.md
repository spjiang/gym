## 1. 背景与目标

会籍与私教/团课已交付。本切片补齐健身房（及同商户模型）的商品库存与前台零售，端侧仅 **Web 管理后台**。

### 1.1 已确认决策

- 端侧：仅 Web 后台
- 能力：分类/SKU、入库出库盘点、低库存预警、零售下单支付出库（PRD 完整档）
- 禁止超卖：库存不足拒绝；库存不得为负
- 支付前二次校验库存，不足则拒付（避免已收款无货）
- 一期不预留锁库存（待支付不占库存）
- 支付继续线下登记 + 线上 mock

## 2. 范围与边界

### 2.1 做

- 商品分类、SKU（名称、单价、单位、条码可选、启停、预警阈值）
- 库存数量；入库 / 出库 / 盘点；库存流水
- 低库存列表筛选（`stock_qty <= low_stock_threshold`；阈值必填，默认 0）
- 零售订单 `order_type=retail`（可关联会员）→ 支付成功履约扣库存
- 全额退款且已履约成功时回补库存
- 权限、审计、测试主路径

### 2.2 不做

- 会员小程序商城
- 多仓/调拨、供应商采购单、批次效期、成本核算
- 营销券/活动价、完整经营报表（仅预警列表）
- 真实微信生产联调

## 3. 领域模型

| 实体 | 要点 |
|------|------|
| ProductCategory | 商户内分类：名称、排序、启停 |
| RetailSku | 分类、名称、单价、单位、条码可选、`stock_qty`（整数）、`low_stock_threshold`、启停 |
| StockMovement | 类型：入库/出库/盘点/零售扣减/退款回补；数量、变动后余量、关联订单可选、备注、操作人 |
| RetailOrderLink + 行项目 | order 关联 member 可选、sku_id + qty + unit_price |

### 3.1 写死规则

- 库存为非负整数
- 入库 `+n`、手工出库 `-n`、盘点设目标值（≥0）记差额、零售履约 `-n`、退款回补 `+n`
- SKU 停用后不可新零售
- 并发：履约时行锁 SKU

## 4. 关键流程

1. 建分类/SKU → 入库  
2. 手工出库 / 盘点  
3. 零售：校验库存 → 建 `retail` 订单 → 支付前再校验 → 履约扣库存写流水  
4. 低库存筛选  
5. 已履约订单全额退款 → 回补库存  

## 5. 权限、API 与前端

### 5.1 权限

| 权限 | 用途 |
|------|------|
| `retail:manage` | 分类/SKU、入出库盘点 |
| `retail:sell` | 零售下单 |
| `retail:read` | 库存/流水/预警只读 |

商户管理员全开；前台 manage + sell + read；教练无零售权限；超管可跨商户。

### 5.2 API（示意）

- `/retail/categories`、`/retail/skus`
- `/retail/skus/{id}/stock`、`/retail/movements`、`?low_stock=1`
- `/retail/orders`；支付钩子 `retail` → `RetailFulfillment`

### 5.3 前端

- 独立菜单/路由 `/retail`（与会籍 `ProductsView` 分离）
- 分类与 SKU、库存操作与流水、低库存、零售收银

## 6. 风险与验收

| 风险 | 对策 |
|------|------|
| 并发超卖 | FOR UPDATE + 支付前校验 |
| 待支付不占库存 | 支付时可能失败，可接受 |
| 命名混淆 | `/retail*` 独立路由 |

**验收：** 分类/SKU/流水正确；库存不为负；预警可筛；零售扣库存；不足拒付；退款回补；测试覆盖。
