# 会员购买协议管理

| 项 | 内容 |
|----|------|
| 日期 | 2026-08-19 |
| 状态 | 待审阅 |
| 范围 | 后台基础配置维护协议；H5 / 小程序购买前勾选并阅读 |

## 1. 背景与目标

H5 会籍「立即购买」目前直接下单支付，没有确认层，也没有会员协议。需要对齐常见购卡弹窗：勾选「我已阅读并同意《协议标题》」，点标题可读全文。协议文案由观野SPACE 后台维护，按商户和购买场景区分，前台按场景拉取。

成功标准：

- 基础配置出现「协议管理」，可按商户维护会籍 / 私教 / 活动 / 餐饮协议
- 该商户该场景没有启用中的协议时，会员端不能完成对应购买
- H5 与小程序购买前必须勾选；未勾选不能支付
- 吧台 POS、前台代售不走会员勾选（员工操作，不在本期）

## 2. 范围

包含：

- 场地级菜单：基础配置 → 协议管理
- 数据：每商户每场景一份（标题、正文、是否启用）
- 会员接口：按 `merchant_id` + `scene` 取当前启用协议
- 会员下单校验：会籍、私教课包、活动报名、餐饮结算
- H5 / 小程序：购买弹窗或结算页勾选 + 全文预览

不包含：

- 零售商城购卡以外的商品协议
- 阅读倒计时（如 7 秒）
- 协议版本表、签署流水、PDF 上传
- 管理端 POS / 前台代办卡强制勾选

## 3. 数据模型

表 `legal_agreements`：

| 字段 | 说明 |
|------|------|
| id | 主键 |
| site_id | 场地 |
| merchant_id | 商户 |
| scene | `membership` / `pt_package` / `activity` / `dining` |
| title | 展示名，如「观野FIT会员协议」 |
| content | 正文，存 HTML（后台富文本） |
| is_enabled | 是否对前台生效 |
| updated_at / updated_by_staff_id | 审计 |

约束：同一 `merchant_id` + `scene` 最多一行（更新即覆盖）。启用后会员端才可见；禁用等于该场景未配置，会员不能买。

场景与下单对应：

| scene | 会员下单 |
|-------|----------|
| membership | `POST /member/orders/membership` |
| pt_package | `POST /member/orders/pt-package` |
| activity | `POST /member/activity-registrations`（含免费确认报名） |
| dining | `POST /member/catering/checkout` |

活动报名即使免费也要勾选：进场规则同样需要告知。

## 4. 接口

后台（权限 `org:read` 列表，`org:write` 写入，与场地介绍同类）：

- `GET /api/v1/agreements?merchant_id=` 分页列表
- `POST /api/v1/agreements` 创建（同商户同场景已存在则 409）
- `PATCH /api/v1/agreements/{id}` 改标题/正文/启用
- `DELETE` 不做物理删，用停用

会员：

- `GET /api/v1/member/agreements?merchant_id=&scene=`  
  返回 `{ id, title, content }`；无启用协议时 400，`code=agreement_required`

下单：上述四个会员写接口在创建订单/报名之前查启用协议，没有则同样 `agreement_required`。不把协议 id 写入订单（本期不落签署）。

## 5. 后台交互

- 菜单位于观野SPACE → 基础配置 → 协议管理（`/platform/agreements`）
- 商户筛选 + 场景筛选；表格：商户、场景、标题、启用、更新时间
- 编辑弹窗：商户、场景、标题、正文（富文本）、启用开关
- 同一商户同一场景已有记录时，创建入口改为编辑已有行

## 6. 会员端交互

会籍 / 私教：点「立即购买」先弹确认层（商品名、价格、有效期），底部勾选「我已阅读并同意《标题》」，点标题打开全文。未勾选确认按钮禁用。确认后再走现有下单 + 支付。

活动报名：报名确认层同样勾选。

餐饮：结算页在提交支付前勾选；未锁桌选桌逻辑不变。

小程序行为与 H5 一致。拉协议失败（未配置）时提示「该门店尚未配置购买协议，请联系门店」，不发起支付。

## 7. 错误处理

| 情况 | 行为 |
|------|------|
| 会员端无启用协议 | 400 `agreement_required` |
| 后台重复创建同商户同场景 | 409 `conflict` |
| 正文或标题为空 | 422 |
| 前台未勾选 | 仅客户端拦截 |
| 商户员工 POS 下单 | 不校验协议 |

## 8. 测试

- 未配置协议时会员购买会籍 400
- 配置并启用后购买成功
- 停用后再次购买 400
- 会员 GET 只返回启用协议的 id/title/content，不含点餐码等无关字段
- 餐饮无协议时 checkout 400；有协议可通过
- 后台同商户同场景第二次 POST 409

## 9. 实现落点（概要）

- 后端：`platform` 模型/API；会员购买与餐饮 checkout、活动报名加校验
- 管理端：菜单、路由、`AgreementsView`
- H5：`HomeView` / `ShopView` 购买弹窗；活动报名；餐饮 `CheckoutView`
- 小程序：首页/商城购卡、活动报名、餐饮结算
