| 项 | 内容 |
|----|------|

| 关联 | PRD 管理后台；`2026-08-05-merchant-qr-acquisition-design.md`（会员来源字段） |
| 范围 | 管理端 Web 主要业务列表的交互与展示约定；服务端分页与检索契约对齐 |

## 1. 背景与目标

当前多数管理端列表偏「整表拉取 + 静态行」，缺少统一的检索区、分页、详情/编辑入口；涉及会员时往往只显示 ID，不利于前台辨认。

### 1.1 已确认决策

| 决策点 | 选择 |
|--------|------|
| 覆盖范围 | **管理端主要列表**均需符合本规范（分批落地，不一口吃完） |
| 与获客关系 | 会员列表/详情必须展示首次来源（平台 / 首进商户），字段来自规格 B |
| 交互 | 列表页具备检索区；行上有详情；可编辑实体有编辑入口；关联用户时展示用户信息 |

### 1.2 成功标准

- 任意已改造列表：可按关键词/关键条件检索，服务端分页，不靠前端硬切全量（大数据表）。
- 行操作至少能进详情；有写权限时可见编辑。
- 订单、会籍、预约等「挂会员」的行，展示会员姓名 + 手机（可脱敏策略统一）。
- 会员列表展示首次来源文案。

## 2. 列表页标准骨架

```
┌─────────────────────────────────────────────┐
│ 标题                         [主操作：新建…] │
├─────────────────────────────────────────────┤
│ 检索区：关键词 + 状态下拉 + 商户 + 日期…  [查询][重置] │
├─────────────────────────────────────────────┤
│ Table（含用户列 / 来源列等）                 │
│  … 操作列：详情 | 编辑 | …                  │
├─────────────────────────────────────────────┤
│ 分页：总数 · 页码 · 每页条数                 │
└─────────────────────────────────────────────┘
```

### 2.1 检索区

- 默认：关键词（名称/手机/单号等按实体定义）。
- 按实体增加：状态、商户（场地账号）、日期区间。
- 「查询」触发重新拉第 1 页；「重置」清空条件。

### 2.2 分页

- 统一查询参数：`page`（从 1）、`page_size`（默认 20，上限 100）。
- 统一响应：`{ items: T[], total: number, page, page_size }`（存量接口可渐进改造；新建接口必须符合）。
- 禁止对无上限的全表 `list` 在前端 `slice` 冒充分页（小目录表如卡种可暂保留全量，但须在任务中标明例外）。

### 2.3 详情 / 编辑

- **详情**：抽屉或独立路由页，只读为主；展示关联用户完整信息与业务字段。
- **编辑**：抽屉/对话框/编辑页；按钮受权限码控制（无权限不渲染）。
- 列表行点击「详情」为默认发现路径；勿只靠「整行不可点且无按钮」。

### 2.4 用户信息展示

凡 `member_id` 非空：

| 展示 | 说明 |
|------|------|
| 姓名 | `member.name` |
| 手机 | 完整或中间四位脱敏（管理端默认完整，配置项可后续加） |
| 首次来源 | 会员场景必显：`综合运营平台` 或首进商户名（规格 B） |

接口：列表 Out 嵌套 `member: { id, name, phone }` 或扁平 `member_name` / `member_phone`，项目内统一一种（推荐嵌套，避免列爆炸）。

## 3. 分批落地顺序

| 批次 | 页面（示例） | 备注 |
|------|----------------|------|
| A1 | 会员、订单 | 与获客来源、用户列强相关；作范式 |
| A2 | 会籍实例、办卡相关、门禁事件 | 健身房核心 |
| A3 | 团课/私教、零售、优惠券、器材 | |
| A4 | 餐饮菜单/订单、员工、商户、通知等 | 目录型可标「全量例外」 |

每批：后端分页检索 → 前端骨架 → 详情/编辑补齐 → 手工冒烟。

## 4. 工程约定

- 前端：可抽 `ListPageHeader` / 检索表单模式，但不强制大而全框架；以约定 + 1～2 个示范页为准。
- 后端：共享 `PageIn` / `PageOut` schema；权限与现网 `require_permission` 一致。
- 文档：改造完成的页在 PRD §10 或本规格验收表勾选。

## 5. 非目标

- 不做通用「元数据驱动 CRUD 生成器」。
- 不在本规格实现商户二维码（见规格 B）。
- 不要求会员端 H5 列表同步改版。
