# 回龙观综合场地健身房管理系统 — PRD 功能模块设计

| 项 | 内容 |
|----|------|
| 日期 | 2026-08-02 |
| 状态 | 待文件审阅 |
| 组织方式 | 平台底座 + 健身房业态包 |
| 技术约束 | 前后端分离；Vue；Python；PostgreSQL；Docker Compose；按需 RabbitMQ |

## 1. 背景与目标

朋友租赁北京市回龙观公园约 1000㎡场地，自营健身房、酒吧等，并招商其他商户入驻。需建设管理系统，门禁使用人脸 Pad，且后台从第一天起兼容「一场地、多商户、多业态」模式。

### 1.1 一期目标

- 健身房完整运营（会籍、课程、教练、商品库存、营销、报表、器材）
- 人脸门禁通行闭环
- 多商户底座（商户类型、商户、员工角色、会员主档、门禁授权）
- 非健身房商户仅使用组织与门禁能力，不做酒吧 POS 等专属功能
- 端侧：Web 管理后台 + 会员小程序/H5 + 人脸门禁 Pad
- 收款：线下登记 + 线上支付（如微信）

### 1.2 成功标准（一期可验收）

- 可配置商户类型并添加健身房/非健身商户；非健身商户仅用组织 + 门禁
- 超管 / 商户管理员 / 前台 / 教练权限可用，且商户数据隔离正确
- 会员一人一档；办卡后 Pad 可放行；过期/停卡拒绝
- 团课预约、私教核销、零售与线上线下支付闭环
- 营销券与经营报表可按商户查看；器材台账与报修可用
- 小程序可完成：查卡、约团课、购卡/买课、支付

## 2. 用户与权限

### 2.1 会员模型

- **场地级主档**：一人一份档案（一期以手机号唯一）
- **商户级授权**：各商户分别授权（会籍、临访、门禁范围等），互不强制同一会籍

### 2.2 后台角色（一期配齐）

| 角色 | 范围 | 主要能力 |
|------|------|----------|
| 场地超管 | 全场地 | 组织配置、跨商户人员与汇总、系统参数、门禁总览 |
| 商户管理员 | 本商户 | 本商业态配置与运营、本商户员工与角色、本商户门禁策略 |
| 前台 | 本商户 | 办卡续费、预约改期、临访、零售、报修；无系统级高危配置 |
| 教练 | 本商户（本人数据） | 课表、名下私教学员/课时、核销、器材报修 |

非健身房商户管理员：仅商户信息、员工、会员授权、门禁相关菜单。

关键写操作（办卡、改权、退款、停卡、角色变更等）需审计留痕。

## 3. 模块架构

```
平台底座
├── 场地与组织（商户类型 / 商户）
├── 账号与权限（RBAC）
├── 会员主档（场地级）
├── 门禁与设备（人脸 Pad）
├── 交易与支付骨架
├── 通知与消息
└── 系统配置

健身房业态包（商户类型 = 健身房时启用）
├── 会籍与卡种
├── 私教与团课
├── 前台运营
├── 商品与库存
├── 营销
├── 报表与财务
├── 教练侧（Web，无独立 App）
└── 健身房设备管理（器材台账与维保）
```

后续酒吧等 = 新增业态包，复用平台底座，不推翻会员主档与门禁模型。

## 4. 平台底座模块

### 4.1 场地与组织

- 场地档案（名称、地址、营业信息）
- 商户类型（健身房、酒吧、零售等，可配置扩展）
- 商户管理（归属场地、类型、状态：筹备 / 营业 / 停用）
- 组织关系：超管看全场地；商户侧仅本商户

### 4.2 账号与权限（RBAC）

- 预置角色：场地超管、商户管理员、前台、教练（可扩展如财务只读）
- 员工账号：归属商户或场地；启停、重置密码
- 数据权限：按商户隔离；超管可切换/查看全部
- 操作审计：关键写操作留痕

### 4.3 会员主档（场地级）

- 基础资料：手机号、姓名、头像、人脸采集状态等
- 商户关系：可被多个商户关联/授权
- 标签与备注（场地或商户维度）
- 防重：同手机号唯一（一期规则）

### 4.4 门禁与设备

- 门禁点（门口、分区门等）及所属商户/公共区域
- 设备（人脸 Pad）：注册、绑定门禁点、在线状态、心跳
- 通行授权：主体 + 门禁点 + 有效期/时段；来源含会籍、临访等
- 通行事件：成功/拒绝、原因、抓拍摘要（最小化存储）
- 人脸下发/失效同步：可异步（RabbitMQ）；开门校验保持低延迟
- 设备凭证与员工/会员登录凭证分离

### 4.5 交易与支付骨架（全业态复用）

- 可扩展订单类型（会籍、课包、零售等）
- 支付：线下登记（现金/转账等）+ 线上（微信等）
- 退款/部分退、支付状态机
- 账单流水，供报表汇总
- 支付回调验签

### 4.6 通知与消息（轻量）

- 一期覆盖：开卡成功、预约提醒、支付结果（站内/小程序订阅或短信预留）
- 非实时、大批量通知与门禁事件解耦，走队列

### 4.7 系统配置

- 场地/商户级参数（营业时段、时区、小程序主题等）
- 字典与枚举（支付方式、卡种状态等）
- 附件存储（协议、头像等）
- 人脸原始生物数据：不在业务库随意落库；按设备方案最小化处理

### 4.8 非健身房商户一期范围

仅使用：商户类型/商户、员工角色、会员授权、门禁点与通行。  
**不做**：酒水点单、台位、配方等业态专属功能。

## 5. 健身房业态模块

### 5.1 会籍与卡种

- 卡种：期限卡、次卡、储值卡（可配置）；价格、有效期/次数、适用门禁、转卡/停卡规则
- 办卡/续卡/升级：订单 → 支付 → 生效会籍
- 生命周期：生效、即将到期、过期、冻结/停卡、作废
- 停卡/延期/转卡（规则可配，操作审计）
- 会籍变更自动同步门禁授权（开通/失效）

### 5.2 私教与团课

- 教练档案：归属、擅长、可授课时段、状态
- 私教课包：课时、适用教练、有效期、售卖与核销
- 团课：课程信息、教室/区域、人数上限、预约/取消时限
- 排课：日/周场次；简单改派/代课
- 预约：后台代约 + 小程序自助约团课；满员策略明确（不可约或简单候补，实现计划中二选一并写死）
- 签到/核销：私教扣课时、团课出席；与会籍/课包联动

### 5.3 前台运营

- 会员快速检索、办卡续费、预约/改期
- 今日预约、会籍状态、通行异常补录授权
- 临访/体验：临时通行（次数或时段）
- 菜单按角色裁剪

### 5.4 商品与库存

- 分类与 SKU、入库/出库/盘点、库存预警
- 零售下单（可关联会员）、支付、出库
- 与会籍/课包订单共用支付与流水骨架

### 5.5 营销

- 优惠券（满减/折扣，适用商品或卡种）
- 活动价/限时价
- 体验课/体验卡（临时期限或次卡）
- 一期不做复杂分销裂变

### 5.6 报表与财务（商户维度）

- 营业汇总：收款、退款、净收；按支付方式与业务类型
- 会籍：新开、续费、在籍、到期、停卡
- 课程：上课量、核销课时、团课满课率/出勤
- 商品：销量、库存简表
- 导出 Excel/CSV；超管可跨商户汇总，商户侧仅本商户
- 一期定位：经营看板 + 流水可对账；不做完整会计总账/税务

### 5.7 教练侧能力（无独立 App）

- Web 后台：名下课表、私教学员/剩余课时、上课核销
- 默认仅本人数据；商户管理员可看全部教练

### 5.8 健身房设备管理（器材，非门禁）

- 台账：名称、分类（有氧/力量等）、品牌型号、资产编号、区域、购入/保修、状态（在用/维修/停用/报废）
- 投放与调拨记录
- 维保：报修单流转；保养到期筛选提醒（一期不做复杂工单引擎）
- 停用/维修设备可标记禁止使用，前台可见
- 权限：管理员增删改；前台/教练报修与查看；超管可跨商户查看
- 一期不做：物联网工况、会员扫码约器械

**与门禁设备边界**：人脸 Pad / 门禁点属平台层；跑步机等器材属健身房业态层。

## 6. 各端触点

### 6.1 Web 管理后台

按角色展示第 4、5 章对应菜单；非健身房商户不展示健身业态菜单。

### 6.2 会员小程序 / H5

- 登录绑定与资料；人脸采集状态展示（采集可在店内 Pad 完成）
- 我的会籍/课包、到期提醒
- 团课预约/取消
- 私教：一期以查看剩余课时为主，预约默认由前台/教练处理（若后续开放小程序约私教，单独加需求）
- 在线购卡/买课包/领券与支付结果
- 本人通行记录、门店信息
- 一期不做：社区、饮食计划、完整训练打卡

### 6.3 人脸门禁 Pad

- 激活绑定、心跳、配置拉取
- 识别 → 校验授权 → 开门反馈；失败原因简示
- 可选店内人脸录入（需员工权限）
- 不做完整业务后台
- 弱网/断网策略在实现计划中选定一种（如短时缓存白名单或失败拒进）并验收

### 6.4 端与模块映射

| 能力 | 后台 | 小程序/H5 | Pad |
|------|------|-----------|-----|
| 组织/权限 | ✓ | | |
| 会员主档 | ✓ | 本人 | 录入/识别 |
| 门禁授权与事件 | ✓ | 本人记录 | ✓ 通行 |
| 会籍/课程/营销/库存/报表/器材 | ✓ | 部分（查、约团课、买、券） | |
| 支付 | 登记+查单 | 线上支付 | |

## 7. 关键业务流程

1. **办卡开通行**：下单 → 支付成功 → 会籍生效 → 写授权 → 异步同步 Pad → 可通行  
2. **团课预约**：选场次 → 校验规则与名额 → 预约 → 提醒 → 到店签到/核销（一期不强制与通行自动签到）  
3. **私教核销**：选课包 → 确认上课 → 扣课时 → 流水  
4. **临访体验**：前台创建 → 短期/次数授权 → 同步 Pad → 到期失效  
5. **退款/停卡**：状态变更 → 收回或暂停授权 → 同步 Pad → 审计  
6. **器材报修**：提交 → 处理 → 完成；设备状态维修/恢复  

## 8. 非功能要求

| 类别 | 要求 |
|------|------|
| 性能 | 通行校验低延迟；报表/批量同步不阻塞开门（重活走队列） |
| 安全 | RBAC + 商户隔离；设备与人凭证分离；支付回调验签 |
| 隐私 | 人脸与身份信息最小化；授权访问；日志脱敏 |
| 可用性 | 后台与小程序常规可用；Pad 在线依赖与弱网行为需明确 |
| 审计 | 办卡、改权、退款、停卡、角色变更可追溯 |
| 扩展 | 商户类型可配；新业态以业态包扩展 |
| 部署 | Vue + Python + PostgreSQL + Docker Compose；按需 RabbitMQ |

## 9. 一期明确不做

- 酒吧 POS / 台位 / 酒水等业态包
- 教练独立 App
- 完整财务总账与税务
- 分销裂变、物联网器械采集、会员约器械
- 多场地连锁集团财务（当前：单场地多商户；模型保留扩展空间）
