## 1. 设计原则

| 原则 | 说明 |
|---|---|
| **按受众分域** | 员工后台、会员端、开放 API 分开，权限与证书策略可独立 |
| **HTTPS 统一入口** | 公网只暴露 443（80 仅做跳转），业务端口不直接对外 |
| **同域反代 API** | Web 端继续用 `/api/v1`，避免 CORS；小程序/回调用独立 API 域 |
| **命名面向产品** | 对外避免 `h5`、`8080` 等技术词，对内文档可保留别名 |

## 2. 推荐域名规划（正式方案）

### 2.1 域名一览

| 用途 | 正式域名 | 说明 | 是否必须 |
|---|---|---|---|
| 管理后台 | `admin.guanyespace.com` | 健身房/清吧/平台运营后台 | ✅ |
| 会员端 | `m.guanyespace.com` | 会员 H5（选店、会籍、点餐等） | ✅ |
| 开放 API | `api.guanyespace.com` | 微信小程序、支付回调、设备/第三方 | ✅ |
| 品牌官网（预留） | `www.guanyespace.com` | 落地页/介绍，可 302 到 `m` | 可选 |
| 根域 | `guanyespace.com` | 301 → `www` 或 `m` | 可选 |

### 2.2 不推荐对外使用的命名

| 域名 | 问题 |
|---|---|
| `www.admin.guanyespace.com` | 多一层 `www`，证书与口述都更绕 |
| `h5.guanyespace.com` | 用户不懂；未来有小程序/App 时语义过时 |
| `123.56.26.229:8080` | 无 HTTPS、无品牌、小程序无法配置 |

### 2.3 对内别名（文档/运维可保留）

| 别名 | 等同 |
|---|---|
| admin | `admin.guanyespace.com` |
| member / m | `m.guanyespace.com` |
| api | `api.guanyespace.com` |

## 3. 流量架构

```
                    Internet (HTTPS :443)
                              │
                    ┌─────────▼─────────┐
                    │  主机 Nginx/Caddy   │  ← Let's Encrypt 证书
                    │  123.56.26.229      │
                    └─────────┬───────────┘
          ┌───────────────────┼───────────────────┐
          │                   │                   │
   admin.guanyespace.com  m.guanyespace.com  api.guanyespace.com
          │                   │                   │
          ▼                   ▼                   ▼
   127.0.0.1:8080      127.0.0.1:8081      127.0.0.1:18000
   (frontend 容器)      (member-web 容器)    (backend 容器)
          │                   │
          └──── /api/ ────────┴──── 反代 ───► backend:8000
```

**说明：**

- `admin`、`m` 的 Nginx 已内置 `/api/` → `backend:8000`（见 `frontend/nginx.conf`、`member-web/nginx.conf`）。
- `api` 域直达后端，供小程序与微信服务器回调，不经过前端静态资源。
- Postgres `35432`、RabbitMQ 等**不对公网开放**。

## 4. DNS 解析

在域名服务商控制台添加（均为 **A 记录** → `123.56.26.229`）：

| 主机记录 | 记录类型 | 记录值 | TTL |
|---|---|---|---|
| `admin` | A | `123.56.26.229` | 600 |
| `m` | A | `123.56.26.229` | 600 |
| `api` | A | `123.56.26.229` | 600 |
| `www` | A | `123.56.26.229` | 600（可选） |
| `@` | A | `123.56.26.229` | 600（可选） |

若已申请 `www.admin`、`www.h5`，可保留并 **301 重定向** 到上表正式域名，避免两套并存。

## 5. 反向代理与 SSL（主机层 Nginx 示例）

在服务器安装证书后，于 `/etc/nginx/conf.d/guanyespace.conf`（路径按实际调整）：

```nginx
# admin — 管理后台
server {
    listen 443 ssl http2;
    server_name admin.guanyespace.com;

    ssl_certificate     /etc/letsencrypt/live/guanyespace.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/guanyespace.com/privkey.pem;

    client_max_body_size 16m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# m — 会员 H5
server {
    listen 443 ssl http2;
    server_name m.guanyespace.com;

    ssl_certificate     /etc/letsencrypt/live/guanyespace.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/guanyespace.com/privkey.pem;

    client_max_body_size 16m;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# api — 小程序 / 支付回调 / 设备
server {
    listen 443 ssl http2;
    server_name api.guanyespace.com;

    ssl_certificate     /etc/letsencrypt/live/guanyespace.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/guanyespace.com/privkey.pem;

    client_max_body_size 16m;

    location / {
        proxy_pass http://127.0.0.1:18000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# HTTP → HTTPS
server {
    listen 80;
    server_name admin.guanyespace.com m.guanyespace.com api.guanyespace.com;
    return 301 https://$host$request_uri;
}
```

证书可用 **Certbot** 或云厂商免费证书；泛域名证书需覆盖 `admin` / `m` / `api` 三个主机名。

## 6. 应用配置对照

### 6.1 服务器 `.env`（`/home/gym/gym/.env`）

```env
APP_ENV=production

# 跨域（管理端 + 会员端；api 域一般不走浏览器 CORS）
CORS_ORIGINS=https://admin.guanyespace.com,https://m.guanyespace.com

# 商户获客二维码、短信链接等
MEMBER_WEB_PUBLIC_URL=https://m.guanyespace.com

# 微信支付异步通知（路径以实际路由为准）
WECHAT_NOTIFY_URL=https://api.guanyespace.com/api/v1/payment/notify/wechat

# 生产建议
SEED_DEMO=false
UVICORN_RELOAD=0
```

### 6.2 Compose 生产覆盖（`docker-compose.prod.yml`）

与基础 `docker-compose.yml` 叠加使用：

```bash
cd /home/gym/gym
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

| 覆盖项 | 开发默认 | 生产 |
|---|---|---|
| `UVICORN_RELOAD` | `1`（热重载） | `0` |
| backend 源码挂载 | 有 | **无**（仅 `backend_uploads`） |
| 端口绑定 | `0.0.0.0` | **`127.0.0.1`**（8080/8081/18000） |
| Postgres 端口 | `35432` 对外 | **不暴露** |
| 重启策略 | 无 | `unless-stopped` |

完整 `.env` 模板见仓库根目录 `.env.production.example`。

### 6.3 前端构建（已在 Compose 中，一般无需改）

```yaml
# docker-compose.yml
frontend:
  build:
    args:
      VITE_API_BASE_URL: /api/v1   # 同域反代，勿写绝对地址

member-web:
  build:
    args:
      VITE_API_BASE_URL: /api/v1
```

### 6.4 微信小程序 `miniprogram/app.js`

```js
apiBase: 'https://api.guanyespace.com/api/v1',
```

### 6.5 微信公众平台 · 服务器域名

| 配置项 | 填写 |
|---|---|
| request 合法域名 | `https://api.guanyespace.com` |
| uploadFile 合法域名 | `https://api.guanyespace.com` |
| downloadFile 合法域名 | `https://api.guanyespace.com` |

业务域名（H5 内嵌页）若需要：`https://m.guanyespace.com`。

## 7. 安全与防火墙

| 端口 | 公网 | 说明 |
|---|---|---|
| 443 | ✅ 开放 | HTTPS 唯一入口 |
| 80 | ✅ 开放 | 仅跳转 HTTPS |
| 8080 / 8081 / 18000 | ❌ 仅 127.0.0.1 | 由主机 Nginx 反代 |
| 35432 (Postgres) | ❌ | 仅内网 |
| 22 (SSH) | ⚠️ 限制 IP | 运维用 |

云安全组：入站仅 `80`、`443`（及受限的 `22`）。

## 8. 与旧地址的迁移

| 旧访问方式 | 新地址 |
|---|---|
| `http://123.56.26.229:8080` | `https://admin.guanyespace.com` |
| `http://123.56.26.229:8081` | `https://m.guanyespace.com` |
| `http://123.56.26.229:18000/api/v1` | `https://api.guanyespace.com/api/v1` |

切换步骤建议：

1. DNS 解析生效（ping / dig 验证）
2. 主机 Nginx + SSL 就绪
3. 复制 `.env.production.example` → `.env`，改密码与域名相关项
4. `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build`
5. 微信后台改合法域名；发版小程序
6. 观察 1～2 天后确认安全组已关闭公网对 `8080/8081/18000` 的直连（prod compose 已绑 127.0.0.1）
